# Database Design

PostgreSQL with Drizzle ORM. Schema source lives in `packages/database/src/schema/<domain>.ts`; migrations in `packages/database/migrations/`.

## 1. Conventions

- Table names: plural `snake_case`. Columns: `snake_case`. TypeScript: `camelCase` via Drizzle mapping.
- Primary keys: `uuid` (UUID v7 generated by the application for time ordering).
- Every table has `created_at timestamptz not null default now()`; mutable tables add `updated_at`.
- Foreign keys are always declared, with explicit `on delete` behavior (default `restrict`).
- Enums: PostgreSQL enums for stable sets (`cluster`, `audit_result`, `provider_status`); text + check constraint when the set is expected to evolve quickly.
- Chain-related rows carry `cluster cluster_enum not null`.
- On-chain amounts: `numeric(39,0)` (fits u128) — never `float`/`double`. Mapped to `bigint` in the domain.
- JSON (`jsonb`) only for provider payload snapshots, extensible metadata, raw external data, and versioned configuration — always with a Zod schema at the boundary.
- Soft deletion only where justified and documented per table.
- Tenant-scoped tables carry `organization_id` with an index; queries always filter by it.

## 2. Roles

| Role | Privileges |
| --- | --- |
| `sct_migrator` | DDL; owns schema objects; used only by migration scripts |
| `sct_app` | `SELECT`, `INSERT`, `UPDATE`, `DELETE` on application tables; **only `SELECT`, `INSERT`** on `audit_events` |

## 3. Iteration 01 schema

```
organizations
  id uuid pk, slug text unique not null, name text not null, created_at, updated_at

users
  id uuid pk, display_name text null, status text check (active|disabled) not null, created_at, updated_at

user_wallet_identities                      -- sign-in identities, not operational wallets
  id uuid pk, user_id fk users, address text not null, cluster cluster_enum not null,
  first_seen_at, last_seen_at, unique(address, cluster)

organization_memberships
  id uuid pk, organization_id fk, user_id fk, status text check (active|suspended),
  created_at, updated_at, unique(organization_id, user_id)

permissions
  key text pk (e.g. 'wallet.read'), description text not null

roles
  id uuid pk, organization_id fk null (null = system role), key text not null, name text not null,
  is_system boolean not null, unique(organization_id, key)

role_permissions
  role_id fk roles, permission_key fk permissions, pk(role_id, permission_key)

membership_roles
  membership_id fk organization_memberships, role_id fk roles, granted_by_user_id fk users null,
  created_at, pk(membership_id, role_id)

auth_challenges
  id uuid pk, address text not null, cluster cluster_enum not null, nonce text unique not null,
  message text not null, issued_at, expires_at, consumed_at null, requester_ip inet null
  index(expires_at)  -- purged by a scheduled job

sessions
  id uuid pk, token_hash bytea unique not null, user_id fk users, wallet_address text not null,
  active_organization_id fk null,
  created_at, last_seen_at, expires_at, revoked_at null, ip_address inet null, user_agent text null
  index(user_id), index(expires_at)

audit_events                                 -- append-only (SPEC-008)
  id uuid pk, occurred_at timestamptz not null, organization_id fk null, actor_type audit_actor_enum,
  actor_id fk users null, action text not null, resource_type text not null, resource_id text null,
  result audit_result_enum not null, request_id text not null, ip_address inet null,
  user_agent text null, cluster cluster_enum null, metadata jsonb not null default '{}'
  index(organization_id, occurred_at desc), index(action), index(actor_id)

provider_health_checks                       -- 1-minute snapshots (SPEC-006)
  id uuid pk, provider_id text not null, cluster cluster_enum not null, status provider_status_enum,
  latency_p50_ms int null, latency_p95_ms int null, error_rate numeric(5,4) null, request_count int not null,
  last_success_at null, last_failure_at null, last_failure_reason text null, checked_at not null
  index(provider_id, checked_at desc)
```

## 5. Migration policy

Forward-only, reviewed, committed. Destructive migrations require explicit human approval and a backup (OPERATIONS.md §5). Each migration that changes a table referenced in API contracts is noted in the changelog.
